§ 07

Help & About

What this tool does

The BEACON WP Effort Planner is a single-file standalone tool for project-level cybersecurity effort planning under ISO/SAE 21434 and UN R155. It uses the full BEACON catalog (66 Work Packages, 172 tasks, 468 MD baseline effort) as its default dataset and produces a closest-possible-GATE estimate based on tailoring decisions and team capacity.

How the calculation works

Effective MD per task = baseline MD × complexity multiplier × overhead inflation.

Complexity multiplier = Simple 0.75×, Normal 1.0×, Complex 1.25× by default. Configurable in Settings.

Overhead inflation = 1 / (efficiency × (1 − meeting load) × (1 − buffer time)). With defaults (80% / 10% / 15%) this is ≈ 1.63×, meaning every 1 MD of pure work content is planned as ~1.63 MD of calendar effort. Configurable in Settings.

WP MD = sum of effective MDs of all tasks. If a WP is tailored out, its MD contribution is zero.

Cumulative gate MD = for gate G, the sum of MD across all WPs whose gate_reqs contains an entry at or below G. By the time gate G is reached, this work must be done.

Quarters at capacity = cumulative MD / total team capacity per quarter (sum across all roles, nominal — the overhead is already baked into the effort).

Closest possible GATE = the latest gate whose required quarters fit between the project start and target end date.

Why overhead applies to effort, not capacity

The same end-result schedule comes out either way (effort × inflation / capacity = effort / (capacity × factor)). Applying the inflation to effort means you see a single MD number end-to-end — the dashboard, gate breakdown, role bars, and per-task figures all show the planning value with overhead included. The pure BEACON baseline remains visible in the catalog row's Baseline column for traceability.

Tailoring & audit

Every change to a task MD value is logged to the Tailoring Log: reductions require a written justification (≥ 20 chars), increases and restorations to baseline are logged automatically. Toggling Active off also requires justification.

Persistence

Default: the planner auto-saves to the browser's localStorage every second (debounced) — there is nothing to set up, your work is preserved across reloads.

For a portable file: click Save to file… in the top bar to pick a location and create a sidecar JSON. Once saved, every subsequent change is automatically written to that file (Chrome/Edge ≥ 122). Use Open file… to resume work from a saved file on another machine.

For backups: Export downloads a one-shot JSON snapshot at any time; Import reads one back. These are independent of the auto-save target.

JSON schema

The database file is human-readable JSON with these top-level keys: project, wps, capacity, tailoringHistory. You can edit it directly in any text editor; reload the page to see changes.
